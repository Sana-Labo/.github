# About the Sana Labo organization on GitHub

This page gives an overview of how the Sana-Labo organization manages its
repositories on GitHub: who receives access, how changes reach protected
branches, and how CI runs. Each topic has its own page.

## Policies

| Topic | What it covers |
| --- | --- |
| [Repository access](https://github.com/Sana-Labo/.github/blob/main/docs/repository-access.md) | Which repository role you receive, how access is granted, and how to request it |
| [Protected branches](https://github.com/Sana-Labo/.github/blob/main/docs/protected-branches.md) | Rules that apply to the default branch, `main`, and `develop` in every repository |
| [CI and runners](https://github.com/Sana-Labo/.github/blob/main/docs/ci-and-runners.md) | How workflows run on pull requests from forks, and rules for self-hosted runners and deployments |

## Contributing

The [contributing guide](https://github.com/Sana-Labo/.github/blob/main/CONTRIBUTING.md)
describes how to work in each role, including working from a fork, opening pull
requests, and writing workflows. A repository's own `CONTRIBUTING.md` takes
precedence over it.

Members can ask an organization owner to request access or to report a problem
with these policies. To report a security issue, follow
[Reporting security issues](https://github.com/Sana-Labo/.github/blob/main/CONTRIBUTING.md#reporting-security-issues).
